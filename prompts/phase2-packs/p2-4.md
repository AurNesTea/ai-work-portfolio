# Step P2-4: Prompt 角色原則注入與 resolved.json 整合

## 任務目標
在步驟執行組裝 prompt 時，將角色定義檔的工作原則以絕對路徑注入標頭；實作路徑字元守衛；並在 `resolved.json` 記錄角色定義檔路徑與送達模式。
撰寫單元測試 `tests/test_packs_delivery.py`。
注意：各 CLI adapter（`cursor.py`, `gemini.py`, `claude.py`）維持不動。

## 規範依據
詳讀 `docs/superpowers/plans/2026-10-16-aiwork-dispatch-and-packs.md` Phase 2「角色原則怎麼送到 CLI」、「P2-4」章節。

## 實作細節
1. **注入條件與格式**：
   - 條件：步驟有 `role`，且在有效目錄（`~/.agents/agents/<id>.md`）找到該角色的定義檔。
   - 若符合，由 runner 組裝 prompt 時，在原始 prompt 最前面加入兩行標頭與一空行：
     ```
     @<role_file_absolute_path>
     請依上面這個角色檔的工作原則執行下面的任務。

     <原始 prompt 內容>
     ```
   - 若步驟沒有 `role`，或該 role 沒有定義檔：prompt 維持逐字不變，不注入任何額外文字。

2. **路徑安全守衛**：
   - 角色定義檔路徑必須轉為正斜線 `/` 絕對路徑。
   - 路徑字元檢查：必須嚴格符合 `^[A-Za-z0-9._:/-]+$`。
   - 若路徑包含空白或非 ASCII 字元：**不加標頭**，記錄 `delivery: none` 並發出警告，避免 cmd / CLI 解析崩潰。

3. **`resolved.json` 記錄擴充**：
   - 在解析與釘住步驟時（`resolve_workflow` / `resolved.json`）：
     - `role_file`: 釘住時解析出的角色定義檔絕對路徑（若無則為 None）。
     - `delivery`: `"prompt-path"` 或 `"none"`。
   - 續跑（resume）時沿用已釘住的 `role_file` 與 `delivery`。

4. **測試 `tests/test_packs_delivery.py`**：
   - 單元測試鎖住：步驟無 role 時 prompt 逐字相同。
   - 步驟有 role 且有定義檔時，prompt 開頭正確注入 `@路徑` 標頭。
   - 測試路徑含空白或特殊字元時，正確退回 `delivery: none` 且 prompt 不含標頭。
   - 測試 `resolved.json` 正確儲存與讀取 `role_file` 與 `delivery`。
