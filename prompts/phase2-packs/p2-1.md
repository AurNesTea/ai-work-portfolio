# Step P2-1: 素材庫結構、驗證器、安全展開與 Manifest

## 任務目標
實作 `src/aiwork/packs.py` 的核心資料結構與安全驗證工具，並撰寫完整的單元測試 `tests/test_packs.py`。
本步驟不碰全域目錄，不碰 UI。

## 規範依據
詳讀 `docs/superpowers/plans/2026-10-16-aiwork-dispatch-and-packs.md` Phase 2「詞彙」、「上傳與驗證」、「P2-1」章節。

## 實作細節
1. **素材庫與檔案結構**：
   - 定義資料結構：`Pack`、`PackItem`、`ManifestEntry`、`Manifest`。
   - 素材包目錄 `<pack-id>/` 含 `pack.yaml`（`id`, `name`, `description`, `version`）。
   - 子目錄包含 `agents/<id>.md`、`rules/<name>.md|.mdc`、`skills/<name>/SKILL.md`。

2. **驗證器 (`validate_pack(path)`)**：
   - 角色檔：frontmatter `name` 等於檔名 stem，`description` 非空，`skills` 為可選字串清單。
   - 規則檔：UTF-8 編碼、小於等於 64 KB、若有 frontmatter 必須可解析。
   - 技能檔：`SKILL.md` 的 `name` 等於父資料夾名，`description` 非空。
   - id 格式：素材包 id 與名稱限 `[a-z0-9][a-z0-9._-]{0,63}`，角色 id 限 `[a-z][a-z0-9-]{0,31}`。

3. **安全展開 (`safe_extract_zip(zip_bytes_or_file, target_dir)`)**：
   - 上傳展開限制：展開後總量 <= 20 MB，檔案數 <= 300，單檔 <= 1 MB。
   - 惡意輸入防護：
     - 拒絕目錄穿越（`..`）、絕對路徑、磁碟代號（如 `C:`）、NTFS 流（含 `:`）。
     - 拒絕 Windows 保留名（`CON`, `PRN`, `AUX`, `NUL`, `COM1`~`COM9`, `LPT1`~`LPT9`）。
     - 拒絕 zip 內的符號連結（symlinks / reparse points）。
     - 拒絕重複檔名大小寫衝突。
     - 展開後路徑經 `resolve()` 必須嚴格在 `target_dir` 之內。
   - 副檔名白名單：
     - 一般允許：`.md`, `.mdc`, `.yaml`, `.yml`, `.json`, `.txt`。
     - 技能目錄內額外允許：`.py`, `.sh`, `.ps1`, `.js`, `.ts`（標記 `has_scripts=True`）。
     - 嚴格拒絕：`.exe`, `.dll`, `.bat`, `.cmd`, `.com`, `.msi`, `.lnk`, `.scr`, `.jar` 及非 UTF-8 文字檔。

4. **Manifest 讀寫 (`applied.json`)**：
   - 儲存於 `~/.aiwork/applied.json`。
   - 記錄寫入的每個檔案：`target_path`, `sha256`, `source_pack`, `item`, `mode` (`file`|`link`|`copy`), `timestamp`, `backup_path`。
   - 支援序列化、反序列化、查詢與 tmp 檔加 `os.replace` 原子寫入。

5. **測試 `tests/test_packs.py`**：
   - 驗證合法素材包通過檢驗。
   - 驗證各類惡意 zip（路徑穿越、NTFS 流、超限、違規副檔名、保留名）全數被攔截且不留殘留檔案。
   - 驗證 Manifest 讀寫與原子替換。
   - 所有測試使用 `tmp_path`，不讀寫真實目錄。
