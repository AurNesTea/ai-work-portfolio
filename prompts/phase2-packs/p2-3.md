# Step P2-3: 角色檔讀寫、技能池掃描與 `aiwork roles` 增強

## 任務目標
實作角色定義檔（`agents/<id>.md`）的序列化與解析、技能池掃描，並在 `aiwork roles` 增加定義與送達狀態欄位。
撰寫單元測試 `tests/test_packs_roles.py`。

## 規範依據
詳讀 `docs/superpowers/plans/2026-10-16-aiwork-dispatch-and-packs.md` Phase 2「角色檔與技能怎麼放」、「P2-3」章節。

## 實作細節
1. **角色定義檔讀寫 (`aiwork/packs.py` 或 `aiwork/roles_def.py`)**：
   - Claude 子代理 Markdown 格式（`agents/<id>.md`）。
   - Frontmatter：
     - `name`: 角色 id。
     - `description`: 說明。
     - `skills`: 技能名稱字串清單（選填）。
   - 本文（Markdown）：工作原則與限制。
   - 序列化時使用 `yaml.safe_dump`，並確保含冒號的字串具備引號包裹（避免 agy 解析問題）。
   - 解析時提取 frontmatter 與 body。

2. **技能池掃描 (`scan_skills_pool()`)**：
   - 外部管理技能：掃描 `~/.agents/skills/*/SKILL.md`。
   - 素材包技能：掃描已啟用素材包下的 `skills/*/SKILL.md`。
   - 回傳可用技能字典：`name` -> 描述與來源。
   - 角色引用的技能若不在池中，標記為「缺」，但不阻擋儲存。

3. **`aiwork roles` 指令擴充**：
   - 列出每個角色時，除原本的 agent、model、effort、source、description 外，增加：
     - `Defined`: 若在 `~/.agents/agents/<id>.md` 或素材庫中有定義檔，顯示檔案路徑；若無則顯示 `no`。
     - `Delivery`: 若已定義且路徑字元合格，顯示 `prompt-path`；若無定義或路徑不合法顯示 `none`。
   - `aiwork roles --json` 也一併帶入 `defined` 與 `delivery` 欄位。

4. **測試 `tests/test_packs_roles.py`**：
   - 測試 Markdown 角色檔之解析與安全序列化（含冒號字元、多技能）。
   - 測試技能池掃描與缺技能偵測。
   - 測試 `aiwork roles` 輸出包含 `Defined` 與 `Delivery`。
