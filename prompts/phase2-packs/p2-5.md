# Step P2-5: 探針指令與快照伺服器端點

## 任務目標
實作 `aiwork packs probe` 探針指令，並在快照伺服器 `panel/scripts/snapshot_server.py` 新增素材庫與機器管理端點，受 `_guard()` 與 `Content-Length` 安全保護。
撰寫單元測試 `tests/test_packs_endpoints.py`。

## 規範依據
詳讀 `docs/superpowers/plans/2026-10-16-aiwork-dispatch-and-packs.md` Phase 2「探針」、「共同限制」、「面板」章節。

## 實作細節
1. **探針核心 (`aiwork packs probe [--agent cursor|claude|gemini]`)**：
   - 於暫存目錄產生一次性探針角色檔（工作原則包含隨機暗號 `[probe-<uuid4>]`）。
   - 以相同 prompt 標頭組裝函式送出極小 prompt，驗證該 CLI 模型回答是否包含暗號。
   - 結果寫入 `~/.aiwork/probe.json`（包含各家 CLI 狀態、檢驗時間、是否通過）。

2. **伺服器端點 (`panel/scripts/snapshot_server.py`)**：
   - 所有新端點均位於 `_guard()` 之後。
   - 上傳端點大小上限：5 MB；其餘 POST 端點上限：256 KB。超過直接回傳 413。
   - 端點清單：
     - `GET /library`: 列出所有素材包、狀態與各項內容。
     - `POST /library/upload`: 上傳單檔或 zip 進入 staging，回傳預覽資訊（清單、雜湊、腳本警示）。
     - `POST /library/commit`: 傳入 upload_id 與 pack_id，驗證後移入素材庫。
     - `POST /role`: 儲存或編輯角色定義檔（寫入預設 `local-roles` 素材包）。
     - `GET /machine`: 取得這台電腦的設定、各 CLI 目錄狀態、啟用素材包與 manifest 一致性。
     - `POST /machine/enable`: 啟用或停用指定素材包。
     - `POST /machine/apply`: 執行套用（支援 `dry_run` 與 `replace` 參數）。
     - `POST /machine/undo`: 執行還原。
     - `POST /machine/probe`: 執行探針並回傳結果。

3. **測試 `tests/test_packs_endpoints.py`**：
   - 測試假 Origin / 錯誤 Host 存取所有新端點，回傳 403 且不動檔案。
   - 測試超量 request body 回傳 413。
   - 測試 upload -> commit -> apply -> undo 完整 API 流程。
