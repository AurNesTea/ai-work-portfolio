# Step P2-6: 前端「角色」頁面實作

## 任務目標
在面板前端實作滿版「角色」設定頁（`panel/src/RoleArea.tsx`），並在 `panel/src/menuPages.ts` 登錄，支援角色管理、素材庫上傳預覽、機器套用與探針檢視。
驗證：`npm run build` 通過，且 1100px 與 800px 寬度不破版。

## 規範依據
詳讀 `docs/superpowers/plans/2026-10-16-aiwork-dispatch-and-packs.md` Phase 2「面板」章節。

## 實作細節
1. **登錄選單頁面**：
   - 在 `panel/src/menuPages.ts` 新增 `{ id: "roles", label: "角色", title: "aiwork 角色與素材", hint: "定義角色原則、技能與素材包套用", component: RoleArea }`。
   - 在 `App.tsx` 的全頁路由中支援 `page === "roles"`，比照 `page === "dispatch"` 與 `page === "usage"` 採滿版整頁模式。

2. **角色設定頁三大區塊**：
   - **區域 1：角色清單與定義編輯**：
     - 列出派工表 id 與定義角色 id 的聯集。
     - 欄位：角色 id、派工摘要（若有）、說明、工作原則摘要、所用技能標籤（缺者紅字標記）、送達狀態（`prompt-path` 或 `none`，附探針指示）、來源（kit／素材包／本機）。
     - 編輯面板：說明輸入框、工作原則 Markdown 文字區域、技能多選勾選框（來自技能池）。
     - 外部管理角色（如 kit 內的角色）設為唯讀並標記來源路徑。
   - **區域 2：素材庫與上傳**：
     - 列出素材庫現有素材包（包含項目清單、說明、版本）。
     - 上傳元件：可選擇單檔、多檔或 ZIP 上傳至 `POST /library/upload`。
     - 入庫預覽：顯示檔案樹、雜湊、腳本警示與安全提醒，確認後呼叫 `POST /library/commit`。
   - **區域 3：這台電腦（Machine Profile）**：
     - 顯示主機名稱與偵測到的 CLI 目錄狀況。
     - 啟用素材包切換開關。
     - 套用按鈕：先出 Dry-run 計畫對話框（顯示將新增、將取代、將建立目錄），確認後真套用。
     - 還原按鈕：一鍵還原到套用前狀態。
     - 探針按鈕與最近一次探針結果（通過／未通過／未登入）。
     - 檔案一致性狀態標籤（正常／手改過／被刪除／已漂移）。

3. **樣式與響應式**：
   - 滿版設計，統一使用 `App.css` 的設計語彙與深淺配色變數。
   - 支援 1100px 與 800px 寬度佈局，無多餘雙層滾動條。
   - 執行 `npm run build` 確認 TypeScript 型別與打包皆無錯誤。
